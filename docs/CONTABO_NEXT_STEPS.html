Architecture reminder

Internet users
    │ HTTPS :443
    ▼
Caddy container (only public ports 80/443)
    │ Docker network "caddy"
    ▼
easyfuel container  →  listens on :5002 (internal only)
    │
    ▼
postgres container  →  host name "postgres", DB "easyfuel"

Your PC (DBeaver) → SSH tunnel → localhost:5432 → postgres

App DATABASE_URL must use host postgres, not localhost. GUI tools use localhost only because of the SSH tunnel.

Why: compose looks for ghcr.io/wasifali9/easy-fuel:latest. That image does not exist until you build and publish it.

Push code to main. GitHub builds the image, pushes it to GHCR, SSHs into Contabo, and runs docker compose up.

Step 2 — Start the EasyFuel container

Where: Contabo SSH · Folder: /opt/easyfuel

cd /opt/easyfuel
ls -la
# Must show: .env  and  docker-compose.yml

docker compose pull          # Path A only (image from GHCR)
docker compose up -d --force-recreate
docker ps | grep easyfuel
docker logs --tail 80 easyfuel

You want logs showing the server listening on 0.0.0.0:5002 and no crash on DATABASE_URL.

Quick internal test (from Contabo):

docker exec caddy wget -qO- http://easyfuel:5002/ | head
After every .env change Recreate the container so new env vars load: cd /opt/easyfuel && docker compose up -d --force-recreate

Rewrite .env completely (if it got duplicated/appended):

rm -f /opt/easyfuel/.env
# Then either paste with nano, OR from your PC:
# scp .env root@169.58.40.94:/opt/easyfuel/.env

# On PC, scp replaces the remote file entirely.
# On server, use:  cat > /opt/easyfuel/.env  (one >)  — never >> (append)

Step 3 — Point Caddy at the app

Where: Contabo · File: /opt/caddy/Caddyfile (shared — edit carefully)

Caddy is the only public entry (ports 80/443). The EasyFuel container has no public ports. Caddy must reverse-proxy the hostname to easyfuel:5002 on the Docker network. 

nano /opt/caddy/Caddyfile

Use this site block (add it; remove the temporary :80 { respond ... } when ready):

portal.easyfuel.ai {
    reverse_proxy easyfuel:5002
}

Reload Caddy (do not restart other apps’ configs carelessly):

docker exec caddy caddy reload --config /etc/caddy/Caddyfile
docker network inspect caddy --format '{{range .Containers}}{{.Name}} {{end}}'
# Expect: postgres caddy easyfuel
Let’s Encrypt HTTPS certificates are automatic once DNS for portal.easyfuel.ai points at this server. If DNS is still on GoDaddy’s old IP, SSL will fail until Step 4.

Step 4 — DNS for portal.easyfuel.ai

Where: your DNS panel for easyfuel.ai (wherever the domain is managed)

  1. Set TTL for portal to 300 seconds if possible (faster cutover/rollback).
  2. Create/update A record:
    • Name: portal (or full portal.easyfuel.ai)
    • Value: 169.58.40.94
  3. Wait a few minutes, then check from your PC: 
    nslookup portal.easyfuel.ai
  4. Open browser: https://portal.easyfuel.ai
Cutover timing If GoDaddy still serves production users, wait to flip DNS until after you migrate the database and storage (Step 6), or accept downtime / dual-write risk. For a first empty-DB test, flipping DNS early is fine.

Step 6 — Migrate production data (Phase 2)

When: maintenance window · From: GoDaddy Windows · To: Contabo

6A. Database

  1. Put GoDaddy app in maintenance / stop writes briefly.
  2. Dump the old Postgres DB (on GoDaddy or wherever DB lives): 
    pg_dump -Fc -h ... -U ... -d Easyfuel -f easyfuel.dump
  3. Copy dump to Contabo: 
    scp easyfuel.dump root@169.58.40.94:/tmp/
  4. Restore into Docker Postgres: 
    docker cp /tmp/easyfuel.dump postgres:/tmp/easyfuel.dump
docker exec -it postgres pg_restore -U creativecloud -d easyfuel --clean --if-exists /tmp/easyfuel.dump

    Admin user on this host is creativecloud (not postgres). Adjust if your dump needs the app owner.

  5. Verify row counts for critical tables: profiles, orders, drivers, customers, suppliers.

6B. Uploaded files (storage/)

The app stores uploads on disk (LOCAL_STORAGE_DIR=/app/storage). Migrating only the DB is not enough — copy the old storage folder into the Docker volume. 

# After container exists, find volume name:
docker volume ls | grep easyfuel

# Example restore into volume (adjust volume name + backup path):
docker run --rm `
  -v easyfuel_easyfuel_storage:/data `
  -v /path/to/storage-backup:/backup `
  alpine sh -c "cp -a /backup/. /data/"

6C. Optional backup script on Contabo

Repo file: scripts/linux/backup-db.sh

bash backup-db.sh ./backups

Step 7 — Cutover & go-live

  1. Final DB dump + storage sync from GoDaddy.
  2. Restore on Contabo; confirm docker logs easyfuel look healthy.
  3. Confirm https://portal.easyfuel.ai works (SSL OK).
  4. Smoke test: login, uploads, WebSocket /ws, payments if staging.
  5. Update Ozow success/cancel/webhook URLs to https://portal.easyfuel.ai/...
  6. Confirm DNS fully points to Contabo.
  7. Stop the old GoDaddy app so it cannot accept webhooks/payments.
  8. Monitor logs 1–2 hours.
  9. Mobile app: set EXPO_PUBLIC_API_URL=https://portal.easyfuel.ai and rebuild if the API URL is baked in.
Rollback plan Keep GoDaddy offline but intact + last dump. If Contabo fails: repoint DNS to GoDaddy, restart old app, restore Ozow URLs to the old host.

Contabo Server — New Project Deployment Guide

Host pattern used by EasyFuel / Inspect360 · Server example: vmi3450363 · IP example: 169.58.40.94 · Updated August 2026

Use this checklist whenever you deploy a new app onto the shared Contabo Ubuntu host. Do not invent a second proxy stack — join the existing Caddy + Postgres + Docker network.

1. Architecture (how this server works)

ComponentLocation / nameRole
Reverse proxy + HTTPS /opt/caddy/ · container caddy Terminates TLS, routes domains to app containers
Postgres container postgres (image postgres:16) Shared DB server; each app gets its own database + user
Docker network caddy (external) Apps talk to caddy and postgres by container name
App folder /opt/<appname>/ Server-only .env + docker-compose.yml
App container e.g. easyfuel, inspect360 No public ports — only reachable via Caddy on the Docker network
Rule: App containers must not publish host ports like 5002:5002. Caddy reaches them as http://<container>:<port> inside network caddy.

3. One-time checklist (new project)

  1. Create DNS A record: domain → Contabo public IP (wait until it resolves).
  2. Create Postgres database + user + grants (see §4).
  3. Create /opt/<app>/ with .env and docker-compose.yml (see §5).
  4. Add Caddy site block and reload Caddy (see §6).
  5. Add GitHub Actions secrets + deploy workflow (see §7).
  6. Build/push first image (or push to main) and confirm container is healthy.
  7. Restore DB dump / run migrations if needed (see §8).
  8. Copy file storage into the Docker volume if the app stores uploads (see §9).
  9. Update payment/webhook/callback URLs to the new HTTPS domain.
  10. Smoke-test: HTTPS loads, login works, API health, webhooks.

4. Create database on shared Postgres

Admin user on this host is often creativecloud (not always postgres). Confirm first:

docker exec -it postgres psql -U creativecloud -d postgres -c '\du'

Then create DB + role (replace names/password):

docker exec -it postgres psql -U creativecloud -d postgres <<'SQL'
CREATE USER myapp_app WITH PASSWORD 'STRONG_PASSWORD_HERE';
CREATE DATABASE myapp OWNER myapp_app;
GRANT ALL PRIVILEGES ON DATABASE myapp TO myapp_app;
\c myapp
GRANT ALL ON SCHEMA public TO myapp_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO myapp_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO myapp_app;
SQL
App DATABASE_URL host must be postgres (Docker DNS), not localhost and not the public IP. 
DATABASE_URL=postgresql://myapp_app:STRONG_PASSWORD_HERE@postgres:5432/myapp

5. App directory on the server

mkdir -p /opt/myapp
nano /opt/myapp/.env
nano /opt/myapp/docker-compose.yml

5.1 Typical .env keys

NODE_ENV=production
PORT=5000
HOST=0.0.0.0
TRUST_PROXY=1
DATABASE_URL=postgresql://myapp_app:...@postgres:5432/myapp
PUBLIC_APP_URL=https://portal.myapp.ai
SESSION_SECRET=...
# + any API keys, Resend, payment gateways, etc.
Never commit the server .env. Keep a private password vault copy.

5.2 Minimal docker-compose.yml pattern

services:
  myapp:
    image: ${MYAPP_IMAGE:-ghcr.io/USER/myapp:latest}
    container_name: myapp
    restart: unless-stopped
    env_file: .env
    environment:
      NODE_ENV: production
      PORT: "5000"
      HOST: "0.0.0.0"
      TRUST_PROXY: "1"
    volumes:
      - myapp_storage:/app/storage   # only if needed
    # NO ports: section
    networks:
      - caddy
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:5000/').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 40s

volumes:
  myapp_storage:

networks:
  caddy:
    external: true

6. Caddy (HTTPS + reverse proxy)

Edit shared config carefully:

nano /opt/caddy/Caddyfile

Add a site block (container name + internal port must match compose):

portal.myapp.ai {
    reverse_proxy myapp:5000
}

Reload (do not recreate blindly if other sites are live):

docker exec caddy caddy reload --config /etc/caddy/Caddyfile
# or from /opt/caddy:
# docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile

Confirm:

curl -I https://portal.myapp.ai
docker ps --filter name=myapp
docker logs --tail 80 myapp

7. GitHub Actions / GHCR deploy

7.1 Repo secrets

GHCR_PULL_TOKENOptional PAT with read:packages if image is private
Build-time tokense.g. VITE_* baked into SPA

7.2 Workflow outline

  1. On push to main: build Docker image → push to ghcr.io/...
  2. SSH to Contabo → docker login ghcr.io → docker pull
  3. docker compose up -d --force-recreate inside /opt/<app>
Day-to-day code deploys: git push origin main. Env-only changes: edit /opt/<app>/.env then recreate the container. DB schema/data is not automatic unless you add a migration step.

8. Database migration / restore

  1. Dump from old host: pg_dump (custom -Fc or plain SQL).
  2. scp dump to Contabo.
  3. Restore, e.g.:
docker cp ./backup.sql postgres:/tmp/backup.sql
docker exec -i postgres psql -U creativecloud -d myapp < /tmp/backup.sql
# or pg_restore for custom format

Then verify table ownership/grants for myapp_app (fix “permission denied for table …” errors).

9. File storage (uploads)

  1. Zip storage on the old server.
  2. Upload to Contabo (WinSCP / scp / Filebin).
  3. Copy into the named Docker volume:
docker volume ls | grep myapp
# Example volume name: myapp_myapp_storage

mkdir -p /tmp/myapp-storage
unzip -o /tmp/storage.zip -d /tmp/myapp-storage
# If zip contains a nested "storage/" folder:
SRC=/tmp/myapp-storage/storage

docker run --rm \
  -v myapp_myapp_storage:/data \
  -v "$SRC":/backup:ro \
  alpine sh -c "cp -a /backup/. /data/ && ls -la /data"

cd /opt/myapp && docker compose up -d --force-recreate

10. Post-deploy verification

  1. https://portal.… loads (valid certificate).
  2. Login / session cookies work (TRUST_PROXY=1, Caddy forwards proto).
  3. docker ps shows container healthy.
  4. App can read/write DB (no permission errors in logs).
  5. Uploads load if storage was migrated.
  6. External webhooks (payments, email) point at the new HTTPS URLs.
  7. Old server DNS removed / app stopped after cutover.

13. Common mistakes

  • Using localhost for Postgres from inside a container → use host postgres.
  • Publishing app ports on the host → conflicts and bypasses Caddy.
  • PUBLIC_APP_URL with http:// → payment redirects / cookies break; use https://.
  • Editing Caddyfile incorrectly → can take down other sites; always reload, then test all domains.
  • Forgetting DB grants → schedulers fail with permission denied for table ….
  • Local Windows .env using Docker paths like /app/storage → wrong for npm run dev; use ./storage locally.
